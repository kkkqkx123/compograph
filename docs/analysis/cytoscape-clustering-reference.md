# 聚类与 P3 功能的 cytoscape.js 对照决策分析

> 版本：v1.0 · 日期：2026-09-30
> 关联文档：[聚类套件分析](./clustering-analysis.md) · [P3 设计决策](../plan/compograph-p3-plan.md) · [功能清单](../architecture/feature-list.md) · [算法差异分析](../ref/graph-algorithms-diff.md) · [AGENTS.md](../../AGENTS.md)
> 事实基线：compograph 本次克隆 `cfd1182`；cytoscape.js 克隆 `7ba6340`，`package.json` 中 `version = 3.35.0-unstable`（`cytoscape.js/package.json:3`）。
> 定位：分析文档，不含实现。本文补齐 `clustering-analysis.md` 第 6 节挂起的 cytoscape.js 逐行核验，并据此给出四类聚类的确定决策；P3 其余六项以速览形式对照。

## 0. 结论摘要

四类聚类中，**层次聚类的 threshold 模式**与**马尔可夫聚类**在 cytoscape.js 中具备可参考的核心流程，但与 compograph 契约有五处必须自行修正的冲突；**均值类聚类**的参考实现带随机初始化与空簇空洞，不能直接照搬；**亲和传播**的参考实现实测存在节点漏分与参数校验缺陷，不建议作为参考实现。

单点启动排序定为：**层次聚类 → 马尔可夫聚类 → 均值类聚类 → 亲和传播**。此结论回改 `clustering-analysis.md` 第 5 节的待定项。

最关键的五个冲突点（详见第 5 节）：cytoscape 返回图元素的活引用而本项目要纯数据；cytoscape 多处依赖 `Math.random` 而本项目要求重复运行一致；cytoscape 的默认参数在三类算法上是退化值；同一聚类家族的输出形态不统一；层次聚类的树模式会往图里写节点。

## 1. 核验方法

### 1.1 核验范围

在 `cytoscape.js/src/collection/algorithms/` 下逐行阅读四个聚类源文件，并交叉核验类型声明 `cytoscape.js/index.d.ts`、官方测试 `cytoscape.js/test/`，以及算法注册入口 `src/collection/algorithms/index.mjs:13-38`。

### 1.2 实测方式

直接以无头模式加载未打包源码（`src/index.mjs`）执行，不经过构建。样本图固定为两团结构：`a,b,c` 在原点附近、`d,e,f` 在 `(100,100)` 附近，两团之间一条弱桥 `c-d`，边权 5 与 0.2。

核验过程中有一处环境事实值得记录：无头模式下元素定义里的 `position` 字段不生效（实测 `{ data:{id:'a'}, position:{x:5,y:7} }` 读回仍为 `(0,0)`），必须用 `node.position({x,y})` 逐点赋值。这一点若不修正会让所有基于坐标的聚类退化成"全部距离为零"从而得出错误结论。

### 1.3 实测结论的可信度

本文所有行为结论均来自实际执行结果，且关键异常项均重复运行 5 次以上确认可复现，不依赖单次观察。

## 3. 四类算法逐一核验

### 3.1 马尔可夫聚类

**流程**：建 n×n 稠密矩阵（`:176`）→ 按边填相似度并对称写入（`:181-190`）→ 加自环（`:49-53`）→ 列归一化（`:55-66`）→ 循环内先扩张后膨胀（`:207`、`:210`）→ 收敛判定（`:213`）→ 按行收集分组成员（`:121-137`）→ 去重（`:139-158`）。

**输入**：边集合，相似度由 `attributes` 中的函数从边上取值，默认恒为 1。

**输出**：`cy.collection(...)` 数组，类型声明为 `NodeCollection[]`（`index.d.ts:3687`）。

**确定性**：无随机源，重复运行完全一致。cytoscape 自身测试也断言"重复十次结果相同"（`test/collection-markov-clustering.mjs:181-196`），并以 MCL 作者官方文档的数值样例作期望值（`:198-207`）。

**实测行为**：

| 场景 | 结果 |
|---|---|
| 默认参数，两团桥接图 | 2 组 `[a,b,c]` `[d,e,f]`，正确 |
| 膨胀系数 6 | 6 组，每点自成一组（粒度随系数变细） |
| 空图 | 0 组 |
| 两个孤立节点 | 2 组，各成一组 |
| 20 点四团（团内成 clique） | 5 组，节点被计数 25/20，**5 个节点同时属于多个组** |
| 30 点五团 | 6 组，节点被计数 36/30，**6 个节点重复归属** |
| 6 点、12 点 | 无重复 |

**代码级问题**：

1. 加自环用赋值而非累加：`M[i*n+i] = val`（`:51`）会覆盖已存在的自环权重。
2. 去重不可靠：`removeDuplicates`（`:148-158`）在双层遍历中对正在遍历的数组执行 `splice(j,1)`（`:153`），会跳过元素导致漏删。上述 20/30 点的重复归属即由此产生。
3. 收敛判定比较的是"扩张输出 `_M`"与"膨胀输出 `M`"（`:213` 传入 `_M` 与 `M`），而非相邻两轮同一阶段的结果，属于近似判定。

### 3.2 均值类家族

一个文件内含三种算法：k-means（`:161-243`）、k-medoids（`:245-324`）、模糊 c-means（`:399-471`）。

**输入**：节点集合 + `attributes` 特征函数（默认空数组）+ 距离度量。**必须预设类别数 k**。

**输出**：k-means / k-medoids 返回 `NodeCollection[]`（`index.d.ts:3703`、`:3718`）；模糊 c-means 返回 `{clusters, degreeOfMembership}`（`:3734-3737`），**形态与同族另外两种不同**。

**实测行为**：

| 场景 | 结果 |
|---|---|
| k=2，两团桥接图，重复 4 次 | 分组内容均正确，但**组的先后顺序在两次运行间发生互换** |
| k=2，固定初始质心（`testMode` + `testCentroids`） | 2 组正确 |
| 默认参数（`attributes` 为空数组） | 全部节点进入同一组，另留 1 个空位 |
| k=3 / k=4 / k=6（6 点 2 团） | 数组长度等于 k，但**存在 1 / 2 / 4 个稀疏空位**，非空组恒为 2 |
| k-medoids k=3 / k=4 | 无空位 |
| k-medoids k=7 > 节点数 6 | 抛出错误（`:254-256` 有 guard） |
| k-means 空图 | 返回 2 个空组，不报错 |
| 模糊 c-means k=2 | 2 组正确，并返回隶属度矩阵 |

**代码级问题**：

1. 初始质心用 `Math.random()` 在特征区间内采样（`:66`），**没有种子机制**。cytoscape 自己的测试必须靠 `testMode: true` 加硬编码 `testCentroids` 才能稳定复现（`test/collection-k-means.mjs:55-56`）。
2. 空簇跳过赋值导致数组空洞：簇为空时 `continue`（`:211-213`），该下标的数组元素从未被写入，形成稀疏空位；而类型声明为 `NodeCollection[]`，声明与实现不符。
3. `attributes` 默认为空数组，此时所有距离为 0，算法退化为"全部归入第 0 组"，默认值不可直接使用。
4. k-means 缺少 k 的上界校验，只有 k-medoids 有（`:254-256`）。

### 3.3 层次聚类

**流程**：每点自成一簇（`:260-270`）→ 计算成对距离并缓存最近邻（`:273-290`）→ 反复合并最近的两簇（`:38-136`）→ 按模式产出（`:303-318`）。支持两种模式：`threshold`（默认，按距离阈值停止）与 `dendrogram`（建树后按深度截断）。

**输入**：节点集合 + `attributes` 特征函数（默认空数组）+ 距离度量 + 连接准则（`min`/`max`/`mean`，其中 `single`→`min`、`complete`→`max` 为别名，`:21-24`）。**不需预设类别数**。

**输出**：实现返回数组（`:320`），但类型声明为 `{clusters, dendrogram?}`（`index.d.ts:3668-3671`），**声明与实现不一致**。

**实测行为**：

| 场景 | 结果 |
|---|---|
| 阈值 0.5 / 1 | 6 组，每点自成一组 |
| 阈值 2 / 50 | 2 组 `[a,b,c]` `[d,e,f]`，正确 |
| 阈值 141 及以上、含默认 `Infinity` | 1 组，全部节点合并（**默认参数无实用价值**） |
| 连接准则 `mean` + 阈值 200 | 3 组 `[b,a]` `[c,f]` `[d,e]`，**分组错误**（b、c 应同属一团） |
| 树模式深度 0 / 1 / 2 / 3 | 1 / 2 / 4 / 6 组，深度 1 时恰好是 `[a,b,c]` `[d,e,f]` |
| 空图 | 0 组（`:243-245` 有 guard，注释说明此前会抛类型错误） |
| 两个孤立节点 | 2 组，各成一组 |

**代码级问题**：

1. 默认阈值 `Infinity`（`:14`）意味着"一直合并到只剩一簇"，默认调用必然得到无意义结果，调用方必须显式给出阈值。
2. `mean` 连接准则的距离更新使用 `c1.size` 与 `c2.size`（`:104`），但簇对象只定义了 `value` / `key` / `index` 三个字段（`:261-265`），`size` 从未被赋值，该表达式求值为非数，这是 `mean` 准则给出错误分组的直接原因。
3. 树模式开启 `addDendrogram` 时会向图内新增节点与边（`:154-175`），**算法调用产生写副作用**，与"只读视图"的假设冲突。
4. `dendrogramDepth` 的语义是沿树递归的层数，不是"切成 k 组"：深度 1 切根节点的左右两支，深度 2 再各切一层。在极度不平衡的树上会退化成逐点剥离。

### 3.4 亲和传播

**流程**：构建相似度矩阵（取距离的相反数，`:56-61`）→ 对角线填偏好值（`:190-193`）→ 交替更新责任矩阵与可用矩阵（`:226-273`）→ 收敛判定（`:276-299`）→ 选代表点（`:81-89`）→ 分配（`:91-150`）。

**输入**：节点集合 + `attributes` 特征函数（默认空数组）+ 偏好策略 + 阻尼系数。**不需预设类别数**。

**输出**：`NodeCollection[]`（`index.d.ts:3754`）。

**实测行为**：

| 场景 | 结果 |
|---|---|
| 两团桥接图 6 点，重复 5 次 | 恒为 2 组 `[a]` `[b,c,d]`，**只覆盖 4/6 节点，e 与 f 丢失**，5 次全部复现 |
| 同图改用均匀分团构造（6/8/9/12/20 点） | 覆盖完整（6/6、8/8、9/9、12/12、20/20） |
| 均匀构造 8 点 2 团 | 1 组，未分出期望的两团 |
| 偏好策略 `max` | 0 组 |
| 空图 | 0 组 |
| 两个孤立节点 | 0 组（未产生任何分组） |
| 不显式传 `damping` | 直接抛错 `Damping must range on [0.5, 1). Got: undefined` |

**代码级问题**：

1. 参数校验发生在默认值合并之前：`setOptions`（`:23-37`）直接读取 `options.damping` 与 `options.preference` 并校验，随后才调用 `defaults(options)`（`:36`）。因此 `defaults` 里声明的 `damping: 0.8` 与 `preference: 'median'`（`:14-15`）形同虚设，调用方必须显式传参，否则抛错。
2. 分配阶段存在漏分路径：`assignClusters` 中仅当 `index > 0` 时才写入（`:106-108`），当某点最近的代表点下标恰为 0 时该点被跳过；且该函数用 `push` 构造数组（`:107`），主函数却按节点下标索引使用（`:315`），两种语义不一致。
3. `assign` 的形参只有三个（`:118`），调用处却传入五个（`:306`），多余实参被静默忽略。
4. 代价最高：默认最大迭代 1000、最小迭代 100，每轮更新两个 n×n 矩阵。

## 5. 与 compograph 契约的冲突点

`clustering-analysis.md` 第 1 节定下的契约是：输入只读图视图，输出与连通分量同形的普通分组集合，顺序确定，空图与孤立节点不报错，计算走后台并受代次守卫。对照后有五处冲突必须在自研时自行修正。

### 5.1 活引用与纯数据

cytoscape 返回 `cy.collection(...)`，是带图上下文的活引用集合，算法甚至能反过来修改图（层次聚类的树模式即如此，`hierarchical-clustering.mjs:154-175`）。本项目现有连通分量返回的是纯数据 `Vec<Vec<NodeIndex>>`（`crates/foundation/cg-graph/src/algo.rs:62`）。**决策：输出纯数据，不引入任何图上下文句柄**，算法不得写回图结构。

### 5.2 随机性与运行一致性

均值类的初始质心依赖 `Math.random()`（`k-clustering.mjs:66`），无种子机制。本项目要求"分组内顺序与分组间顺序均按端点排序，保证重复运行结果一致"。**决策：若实现均值类，初始中心必须由调用方显式传入或由确定性规则选出（例如按端点序取前 k 个），禁止内部取随机数**；输出统一按端点排序后再返回。

### 5.3 默认参数不可直接沿用

四类中有三类的默认值是退化值：均值类与层次聚类的 `attributes` 默认为空数组、层次聚类阈值为无穷、亲和传播缺阻尼即抛错。**决策：不在算法内部放置"兜底默认值"，类别数与阈值这类决定粒度的参数一律由调用方显式传入**，缺失时按错误口径报告首个相关节点，而非静默产出无意义分组。

### 5.4 输出形态不统一

同一家族内模糊 c-means 返回结构而另外两种返回数组（`index.d.ts:3734-3737` 对 `:3703`）；层次聚类的声明与实现也不一致（`index.d.ts:3668-3671` 对 `hierarchical-clustering.mjs:320`）。**决策：四类统一返回同一种分组类型**，不引入"隶属度矩阵"等附加形态；若将来确有需要，另起模块而非改动统一契约。

### 5.5 副作用与只读视图

层次聚类的树模式会向图中写入节点与边。**决策：聚类一律以只读视图实现，任何算法都不得新增或修改图元素。**

## 6. 四类聚类的设计决策

| 算法 | 决策 | 可借鉴的部分 | 必须自行修正的部分 |
|---|---|---|---|
| 层次聚类 | 可作首选单点启动 | 凝聚流程、成对距离与最近邻缓存、距离阈值的截断语义（`hierarchical-clustering.mjs:260-297`） | 阈值必须显式传入；只做单连接（最小距离）准则，不做均值准则（其参考实现本身有误）；不做树写入；输出按端点排序 |
| 马尔可夫聚类 | 次选 | 扩张—膨胀交替主循环、自环与列归一化、收敛判定思路（`markov-clustering.mjs:192-218`） | 成员收集改为"每点归属唯一组"，不采用按行收集再去重的做法（参考实现会重复归属）；矩阵稠密存储需评估规模上限 |
| 均值类聚类 | 第三顺位 | 迭代式归属—更新中心的骨架（`k-clustering.mjs:192-240`） | 初始中心必须确定化；空簇必须显式处理（返回空组或报错，不留空洞）；类别数由调用方传入；读坐标表，须与代次守卫配合 |
| 亲和传播 | 最后，且不参考其实现 | 仅参考"消息传递选出代表点"的思路 | 参考实现存在漏分与参数校验缺陷，按本文第 3.4 节结论自研；代价最高，须严格后台执行 |

关于马尔可夫聚类的成员收集：参考实现先按行收集再全局去重（`markov-clustering.mjs:121-158`），实测在 20 点与 30 点图上出现重复归属。**自研时应直接按"吸引子—被吸引点"归属关系一次性构造分组，保证每点恰好属于一组**，去重步骤不再需要。

关于层次聚类的连接准则：参考实现的 `mean` 准则因 `size` 字段未初始化而失效（`:104` 对 `:261-265`）。**自研只实现单连接（最小距离）准则**，该准则下的距离更新只需取两个已有距离的最小值，无需维护簇规模。

## 7. 单点启动排序（确定方案）

排序由两个因素决定：无头可测性与参数风险。

1. **层次聚类**——无需预设类别数，输入为距离即可，无随机源，小图断言合并关系即可，且单连接准则实现最短。
2. **马尔可夫聚类**——无需预设类别数，确定性强，但需稠密矩阵，规模上限要先评估；膨胀系数是唯一敏感参数。
3. **均值类聚类**——必须预设类别数，且依赖当前布局坐标，需配套代次说明；初始中心若不人工给定则结果不可重复。
4. **亲和传播**——收敛代价最高，参数最敏感，且参考实现实测存在漏分，排序最后。

此排序回改 `clustering-analysis.md` 第 5 节（原为待定）与第 6 节（原为待补充）。

## 10. 验收口径

沿用无头单测，断言分组关系而非浮点数值。每个算法至少覆盖：

1. 两团桥接小图得到两组，且成员集合精确相等。
2. 空图返回空分组，不报错。
3. 孤立节点的行为符合该算法的既定约定（自成一组或归入最近组），且结果稳定。
4. 重复运行（不少于 10 次）输出完全一致，包括分组之间的先后顺序。
5. 每点恰好属于一个分组，不存在重复归属或漏分——这是本次对照中参考实现暴露最多的缺陷，必须列为必测项。
6. 参数缺失或非法时按错误口径报告，不 panic、不静默产出无意义结果。

界面侧统一走后台任务与代次守卫，性能贵的操作不得进入绘制路径。
