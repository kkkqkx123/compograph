## 0. 范围与非目标

阶段 3 收口为“万级图可交互”：平移缩放跟手，帧时间与内存有量化记录，路线取舍有书面结论。对应功能清单中标为 P3 的渲染与调度主体。

在范围内：帧时间与内存基线度量、细节层次、边聚合（干草堆与折线）、空间索引与视口剔除的规模化改造、保留模式元素、后台布局调度补齐（取消与重启语义、进度回写）、图片导出、路线 C 限时评估与决策记录、应用侧组装（状态栏帧信息、聚合开关、导出入口）。

不在范围内（明确不做）：完整样式 schema 扩张、标签文本系统重做、中心性家族与聚类等远期自研算法、CSS 选择器字符串、十万级生产可用的实例化渲染管线。路线 C 本阶段只产出评估结论与原型数据，不进入默认绘制路径。动画过渡不做，布局切换仍即时落位加后台精化。

## 1. 出发点现状

阶段 2 落地后：六种以上布局可切换，样式表加旁路覆盖生效，框选多选与悬停可用，算法面板五项可后台执行，JSON 与 DOT 出入口可用。

与规模化相关的缺口集中在五处，且均不推翻既有文件，只在其上扩展：

- 绘制为即时模式：渲染视图每帧重建全部边路径（逐边构建描边路径、按颜色分组构建箭头路径、逐节点构建矩形），空间索引在根视图绘制函数内每帧重建。节点与边规模翻倍时，每帧工作量线性增长，无缓存。
- 相机只有单一精度：无论缩放比多少，边始终按贝塞尔绘制，箭头始终生成，尚无按缩放降级的概念。
- 边几何只有直线、单贝塞尔、自环三种：平行边按对称偏移散开，大图下控制点计算与逐边路径构建成为帧热点，尚无面向密图的简化边形。
- 后台调度只有雏形：布局驱动对力导向按块推进并以代次作废旧任务，非力导向引擎走同步回退，结构变更的反应仍同步执行。算法面板各自派生后台任务并以代次守卫，无统一队列与进度语义。
- 度量缺失：尚无帧时间、绘制计划规模、内存占用的统一记录口径，无法判断优化是否生效。

## 2. 任务分解

### 任务一：度量基线与合成基准图

目的：先有尺子再优化，所有后续任务以同一口径报告收益。

做法：在渲染 crate 新增轻量度量记录（每帧绘制计划的节点边箭头计数、计划构建耗时、索引重建耗时），应用侧状态栏汇总最近若干帧的平均值。基准图以确定性合成图承担：网格加随机边、链式加跨层边两类，规模覆盖一千、五千、一万三档，种子固定。内存口径取绘制计划向量长度与索引单元数的估算值，不引入进程级剖析依赖。

取舍：不做火焰图与 GPU 计时，CPU 侧耗时加计数已足够指导取舍；基准图不入库，只在基准测试代码内生成。

验证：同文件单测覆盖计数口径；基准测试在目标机记录三档规模的帧时间表，作为任务四与任务八的对比基线。

### 任务二：细节层次

目的：缩放缩小时用视觉降级换帧率，这是万级图最廉价的优化。

做法：在渲染 crate 新增细节层次模块，输入为相机缩放比与可见元素计数，输出为当前层次。层次至少三档：完整档（曲线边加箭头加节点块）、简化档（边退化为直线、箭头按需保留、自环仍绘制但不细分）、极简档（节点退化为方块、边全部直线且无箭头、标签与悬停浮层隐藏）。阈值做成可调参数并带回滞区间，避免在临界缩放下来回跳变。绘制计划生成函数按层次分支，命中测试侧保持全精度（点选仍按曲线判定，不因视觉降级而误判）。

设计来源：借参考实现视口选项（隐藏边、视口纹理、动态模糊开关）的分档思想，阈值与落点全部重写为本项目的矩形与路径原语。

验证：同文件单测覆盖阈值边界与回滞行为；人工验收为缩小到极简档后帧率回升、放大后细节恢复，点选精度不变。

### 任务三：边聚合几何

移植来源：参考实现边控制点模块的干草堆分支与折线分支。

干草堆做法：在几何 crate 新增干草堆端点函数。参考实现按随机角度取源端与目标端方向并按半径缩放，本项目把随机改为确定性散列（由边两端标识推导方向），半径取节点尺寸倍数加可调参数。聚合边绘制为直线段，命中测试复用既有线段距离函数。激活条件为密度开关：边数超过阈值或调用方显式指定时，平行束整体改走干草堆，不再逐边求贝塞尔控制点。

折线做法：在几何 crate 新增正交折线函数，至多两次转向，方向缺省按端点差的长边自动判定，亦可由调用方指定水平或垂直优先。绘制为折线路径，命中测试走折线逐段距离。首批只服务手动指定走向的边，不做自动布线。

取舍：参考实现的手动端点、相交点、端点距离等分支一律舍去；干草堆的随机播种改为散列，保证相同输入两次输出一致。

验证：同文件单测覆盖干草堆端点落在节点附近、相同边两次结果一致、折线段数上限；绘制计划单测覆盖聚合边不再携带贝塞尔控制点。

### 任务四：空间索引与视口剔除的规模化改造

目的：把每帧全量工作改为可见驱动，这是保留模式的前置。

做法：空间索引由每帧重建改为版本化持有：结构变更与位置写回时重建，可见性变化（平移缩放）不重建。格长按节点尺寸倍数自适应，不再使用固定常量。绘制计划生成改为先经索引矩形查询取可见节点集，再只为可见节点与其关联边生成计划；贝塞尔边以控制多边形包围盒参与剔除的既有做法保留。边索引暂不单独立项，边可见性由端点可见性加包围盒测试推导。

验证：同文件单测覆盖大视口外节点不再进入计划、索引版本未变时复用；基准测试对比改造前后的计划构建耗时。

### 任务五：保留模式元素

目的：把路线 A 的每帧重建改为按变更差异刷新，这是本阶段核心。

做法：在渲染 crate 新增保留元素模块，实现界面框架的元素契约（布局请求、预绘制、绘制三段）。元素持有缓存的节点计划、边计划、箭头计划与四类版本号（结构代次、位置代次、样式代次、相机视口快照）。刷新规则为结构变更重建索引与受影响束，位置变更只更新移动节点与其关联边，样式与旁路变更只更新受影响元素，相机变化只重投影（不重算几何）。绘制段只遍历缓存并按颜色分组发射图元，保持场景按图元类型批处理的低状态切换特性。过渡期保留即时模式入口，保留元素以开关切换，缺省仍走即时模式直到验收通过后再翻转缺省。

平台落点：节点沿用矩形填充原语，边沿用路径描边原语，箭头沿用填充多边形，相机变换仍走 CPU 仿射，进阶的矩阵变换留给路线 C 评估。

验证：无界面单测覆盖四类变更的缓存命中与失效（移动一节点只脏其关联边，改一节点样式不碰其余计划）；测试上下文验证结构变更经订阅触发刷新；渲染仍只测计划数据，不测像素。

### 任务六：后台布局调度补齐

目的：布局完全移出界面线程，大图下界面不卡顿，且取消语义正确。

做法：扩展布局驱动为统一调度器。已有代次计数保留并推广到全部引擎：任何新变更、引擎切换、拖拽精化均递增代次，旧任务的迟到回写一律作废。非力导向引擎不再无条件同步执行：小图（节点数低于阈值）仍同步落位保响应，大图改走分块后台执行，块大小与每帧最多一次回写的节流共用同一参数。拖拽中的节点保持固定并走局部精化，不触发全量重启。进度（当前代次、已回写块数、最近耗时）暴露给状态栏，取消为协同式（任务在块边界检查代次），不做抢占。

取舍：不做优先级队列与多布局并发，同一时刻只运行一个布局任务；算法后台任务仍各自独立，仅复用代次守卫思想，不并入布局调度器。

验证：测试上下文覆盖取消后无野回写、引擎切换作废旧任务、拖拽精化不丢固定点；人工验收为万节点力导向启动后界面仍可平移缩放，中途切换布局旧结果不再覆盖新结果。

### 任务七：图片导出

目的：规模化场景需要可分享的静态产出，且导出路径可复用绘制计划。

做法：应用侧新增导出入口，支持当前视口与全图包围盒两种范围、倍率参数。实现复用保留元素的缓存计划并按倍率缩放，不重新跑布局。平台截图能力可用时优先用其截取视口，包围盒导出与无截图能力的平台走软件光栅回退。导出为后台任务，避免阻塞画布，状态栏报告结果。

取舍：不做矢量导出与分层导出，只做像素图；中文标签换行等文本细节沿用既有文本能力，不在本任务内重做。

验证：往返测试覆盖包围盒计算、倍率缩放后的图像尺寸；人工导出两种范围各一 Opening 图。

### 任务八：路线 C 限时评估

目的：以数据决定十万级路线是否立项，而非凭感觉保留。

做法：以限时原型的形式进行，设上限（如不超过本阶段三分之一工期），到期无论结论如何都封存。原型基于分支上公开的图形设备与队列访问能力，自建最小实例化管线：节点为实例化矩形、边为实例化线段，单个着色器加单一变换矩阵。架构参考引用实现实例化绘制模块的批量抽象（按类型分批、按实例传参），着色器与管线代码全新实现，不移植其着色器源码。对比维度为一万、五万、十万三档合成图的帧时间与内存，原型代码置于独立特性门后，永不进入默认绘制路径。

产出：评估记录含三档数据、与保留模式的对比表、保留或放弃的明确结论。放弃时删除原型管线代码，只保留记录；保留时另立后续阶段，不在本阶段产品化。

验证：以基准测试数据为准，不以肉眼感觉为准；决策记录随文档入库。

### 任务九：应用侧组装

做法：根视图持有保留元素开关、细节层次指示、布局进度、导出状态四个新增显示项；绘制时先经细节层次定档再取保留缓存或即时计划；工具栏新增聚合开关与细节层次指示，状态栏新增帧时间、可见计数、布局耗时与进度；出入口菜单接图片导出。窗口尺寸变化沿用既有视口更新，视口变化只触发重投影而不触发几何重算。

## 3. 横切约束

确定性：聚合方向、基准图、布局种子全部确定性可复现；干草堆禁用运行期随机。

安全与风格：生产代码禁用解包，缺失坐标的边一律跳过；动态派发仍仅保留引擎注册表一处，保留元素不新增 trait 对象；依赖方向不变，几何不依赖界面框架，布局不依赖渲染，度量模块不引入界面类型。

测试分层：纯计算走同文件单测并与参考算例对拍；缓存失效与后台调度走测试上下文；渲染只测绘制计划数据，不测像素；性能走合成基准，不以人工感觉为准。

---

## 4. 建议实施顺序

度量基线先行，其次细节层次与边聚合几何并行，再空间索引改造，然后保留模式元素，接着后台调度补齐与应用组装，最后图片导出与路线 C 评估。保留元素依赖索引改造的结论，后台调度依赖块推进接口稳定，路线 C 与其他任务无依赖可独立推进但不得阻塞收口。

---

## 5. 验收标准

- 万级节点图可平移缩放，操作跟手，帧时间与内存有三档规模的量化记录。
- 细节层次在阈值处自动切换且带回滞，视觉降级时点选精度不变。
- 密图下聚合边自动生效，相同输入两次渲染一致。
- 保留模式下移动单节点只刷新其关联边，主样式不受污染；开关切回即时模式行为一致。
- 后台布局可取消可重启，旧任务迟到回写被丢弃，拖拽固定点不丢失。
- 图片导出两种范围可用，后台执行不阻塞画布。
- 路线 C 有书面评估结论（保留或放弃），含三档规模的对比数据。
- 自研 crate 全量测试通过，无新增裁剪告警，格式化通过。
- 手动操作脚本：大图加载、缩放穿越层次、聚合开关、后台布局取消、图片导出五步，每步有可见预期。

---

## 6. 风险与回退

保留元素若受界面框架版本漂移影响，则保留即时模式入口并推迟缺省翻转，正确性不受损。细节层次若出现临界抖动则加宽回滞区间，阈值改为可调参数。聚合视觉若不符合预期则收紧激活阈值，缺省只在超密图启用。后台调度若出现饥饿则小图退回同步落位，大图阈值上调。路线 C 若超时或数据无优势则按放弃处理，保留模式加细节层次即为本阶段的交付形态，不影响收口。
