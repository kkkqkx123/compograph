# 他项目接入设计方案

> 版本：v1.0 · 日期：2026-10-02
> 目标：说明其他项目如何引用本项目作为图可视化库并复用其顺带提供的 gpui。
> 约束：本库不提供 UI 组件与后端方案，只保证图侧能力与版本对齐方式；规划文档不贴大段代码。

---

## 1. 引用方式

- 以 git 固定 rev 引用本仓库的库 crate，不引用演示二进制。版本号跟随本仓库的 submodule 指针同步升级，不自行浮动。
- gpui 与本库同基线引用，保持与本仓库一致的上游快照版本，避免两边 gpui 不一致导致的签名错位。
- 工具链与本仓库钉定版本保持一致，网络受限环境沿用既有的镜像与代理配置。
- 上游快照只读，不修改不格式化；确需改上游时走上游仓库流程，本项目与消费方均只升级指针。

## 2. 依赖搭配

- 只做算法与布局：引用几何基元、图存储与布局三个 crate，不拉渲染链。
- 完整画布：再加渲染与交互 crate，按分层 DAG 方向依赖，不反向依赖演示层。
- 图元素标识统一使用本仓库重导出的索引类型，不直接依赖 petgraph。
- gpui 的平台后端仅由最终二进制引入，库 crate 不带平台后端，保证无头测试可用。
- 窗口测试能力只出现在开发依赖中，正常构建不启用。

## 3. 运行时接线

- 图状态由实体持有，经变更事件广播；布局驱动订阅图变更维护坐标，渲染订阅位置变更重绘。消费方按需订阅并声明过滤条件，避免全量刷新。
- 后端数据先在消费方侧做差异比较，再调用图存储增删改；布局与重绘由订阅链自动跟进，不做全量重建。
- 外部稳定 id 由消费方在文档侧维护：导入文档以标识对齐，导出文档携带标识，本库内部统一使用索引类型，不保留双向映射表。
- 画布嵌入消费方窗口：相机负责视口映射（含 `fit_to_bounds` 按包围盒适配），拾取经空间索引完成，样式覆盖经旁路存储生效。消费方自管窗口、主题与面板，本库不介入。
- 编辑场景下交互层只产出 `EditAction` 值（配套 `EditTool` 与连边草稿），校验、撤销与业务规则由消费方在应用层处理后写回图存储。
- 过渡场景下消费方提交样式目标值，本库以 `NodeStyleTransition` 与 `EdgeStyleTransition` 做逐帧插值，由调用方按重绘节奏推进，不感知业务状态含义。

## 4. 升级与排错

- 本仓库升级上游指针后会重查签名并同步文档基线；消费方跟随升级固定 rev 即可，不单独跟踪上游分支。
- 若出现上游继承解析失败，通常是快照未初始化或指向未展开内容，先按既有 submodule 指南重新初始化再排查。
- 若出现 gpui 签名错位，以本仓库基线为准对齐，不在消费方侧打补丁。

## 5. 非目标

通用组件、编辑器、主题、后端客户端、领域面板、校验回放、多窗口均由消费方在 gpui 之上自建，不在本方案的保证范围内。

## 6. 暂缓功能归属

本体只守三条可扩展契约：只读图视图、坐标外挂加变更事件、绘制计划加布局 trait。重依赖、高耦合、投机性框架一律不进本体；影响视觉一致性的精修一旦立项必须在本体统一口径，避免下游分叉。

适合下游自建的四项：

* 路线 C wgpu 实例化：十万级才需要的实例化几何加样式批加纹理拾取。当前即时绘制加保留场景加细节分级加空间索引已覆盖数百到数万规模。与上游升级耦合最深，目标规模未定前本体不做。下游真到十万级时基于只读视图和坐标另起渲染后端，直接使用分支已公开的设备队列，本体只需保证视图契约稳定。
* 扩展机制：通用插件框架。本体是应用而非通用库，没有第二个消费者，不抽象通用扩展点。下游要自定义布局或覆盖层时在自己侧实现布局 trait 并注册，出现多个同类需求后再回本体提炼。
* GraphML：与外部图工具互换的 XML 格式。当前 JSON 已承担结构加坐标持久化，DOT 已承担简单图互换。XML 解析依赖和键映射负担重，无产品约定的文件对话承诺时本体不做，下游需要时基于公开的图文档结构自写转换。
* 背景图：节点体内贴本地图片。当前只有规格和缓存状态机加缺失回退，无解码器，无画布和光栅消费，远程路径已拒绝。完整管线需解码依赖加异步解码加缓存驱逐加导出消费，且离线部署只能走本地文件，在出现真实本地用例前继续冻结。下游要头像类节点时复用已有图片规格和缓存键自接解码和绘制。

暂缓但将来只能在本体做的三项：

* 复合布局引擎内约束：把父子包含和分组斥力写进力导向迭代内部。当前扁平引擎加驱动后处理已分层正确，引擎数学保持干净。若后处理被实测证实压不住嵌套抖动，再在本体内加约束变体并配套统一测试，不由下游自改力场，以免与容器裁剪命中口径脱节。
* 边标签旋转绘制：沿边切向旋转文字。当前锚点和角度计算、包围盒和框选已按旋转生效，只有画布保持水平绘制以保证可读性。若产品明确要求贴边文字，只能在渲染层统一改绘制与命中同口径，不由下游自画覆盖层。
* PNG 带标签导出：从纯几何变为所见即所得。当前软件光栅加自研编码刻意只覆盖节点边几何，标签留画布。标签导出涉及离屏字体整形和换行对齐，需与画布同口径才能保证归档一致，无明确出版级需求前保持几何最小闭环，不由下游各自实现。

## 7. 调用方扩展目录

以下均取自差距分析中的可用性缺口，本体只提供无头可测的地基，界面与业务语义由调用方在 gpui 之上自建。地基本体已具备，不因演示应用未接线而视为缺失。

* 视口接线：平移手势取舍、中键或空格临时平移、启动 fit、一键适应视图、重置、行为开关、视口事件消费。库侧已有位移与包围盒适配能力，调用方按自家交互习惯接线即可，空白左键归属框选还是平移由调用方拍板。
* 图编辑界面与业务：双击空白新建、删除键删除选中、连边工具加预览加取消、标签与权重与自由属性就地编辑加非法输入拒绝、边重连界面入口、右键三态菜单、快捷键注册表、命令面板。交互层只产出结构变更请求值，校验、撤销栈、业务规则、栈深上限由调用方持有后写回图存储。
* 语义事件消费：点按、双击、右键、拖拽、释放、抓取、选中变化、框选起止的归一化消费，命名空间与单次订阅、按选择器委托。库侧状态机产出值对象，调用方映射到自家事件总线。
* 选择器与集合用法：查询入口输入框或命令行、集合运算组合、邻域与闭包查询的领域编排。库侧提供类型化选择器与样式表求值，不提供字符串选择器语言，调用方不自造方言。
* 样式用法：默认样式加用户规则表填充、命中顺序、类名增删改接线、数据映射区间配置、标签对齐与背景选择、曲线样式开关暴露、样式表导入导出界面。库侧三层解析与样式插值只做求值与逐帧混合，主题与面板归调用方。
* 动画与布局驱动：视口动画按帧推进、样式过渡按重绘节奏推进、布局通用选项接线、布局生命周期展示与显式中断接线。库侧插值与代次守卫保证过期帧不提交，帧循环由调用方驱动。
* 导入导出策略：按标识的保留与更新与新增与删除合成、冲突处理、样式序列化菜单、标签是否进导出图。库侧保持整体替换与纯几何导出为稳定最小语义，合成策略与报表需求由调用方定。
