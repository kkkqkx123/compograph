# 他项目接入设计方案

> 版本：v1.0 · 日期：2026-10-02
> 目标：说明其他项目如何引用本项目作为图可视化库并复用其顺带提供的 gpui。
> 约束：本库不提供 UI 组件与后端方案，只保证图侧能力与版本对齐方式；规划文档不贴大段代码。

---

## 1. 引用方式

- 以 git 固定 rev 引用本仓库的库 crate，不引用演示二进制。版本号跟随本仓库的 submodule 指针同步升级，不自行浮动。
- gpui 与本库同基线引用，保持与本仓库一致的上游快照版本，避免两边 gpui 不一致导致的签名错位。
- 工具链与本仓库钉定版本保持一致，网络受限环境沿用既有的镜像与代理配置。
- 上游快照只读，不修改不格式化；确需改上游时走上游仓库流程，本项目与消费方均只升级指针。

## 2. 依赖搭配

- 只做算法与布局：引用几何基元、图存储与布局三个 crate，不拉渲染链。
- 完整画布：再加渲染与交互 crate，按分层 DAG 方向依赖，不反向依赖演示层。
- 图元素标识统一使用本仓库重导出的索引类型，不直接依赖 petgraph。
- gpui 的平台后端仅由最终二进制引入，库 crate 不带平台后端，保证无头测试可用。
- 窗口测试能力只出现在开发依赖中，正常构建不启用。

## 3. 运行时接线

- 图状态由实体持有，经变更事件广播；布局驱动订阅图变更维护坐标，渲染订阅位置变更重绘。消费方按需订阅并声明过滤条件，避免全量刷新。
- 后端数据先在消费方侧做差异比较，再调用图存储增删改；布局与重绘由订阅链自动跟进，不做全量重建。
- 外部稳定 id 与库内索引的映射使用本库 `IdMap`，保证双向可查并在删除与整图重置后扫除失效条目。
- 画布嵌入消费方窗口：相机负责视口映射（含 `fit_to_bounds` 按包围盒适配），拾取经空间索引完成，样式覆盖经旁路存储生效。消费方自管窗口、主题与面板，本库不介入。
- 编辑场景下交互层只产出 `EditAction` 值（配套 `EditTool` 与连边草稿），校验、撤销与业务规则由消费方在应用层处理后写回图存储。
- 过渡场景下消费方提交样式目标值，本库以 `NodeStyleTransition` 与 `EdgeStyleTransition` 做逐帧插值，由调用方按重绘节奏推进，不感知业务状态含义。

## 4. 升级与排错

- 本仓库升级上游指针后会重查签名并同步文档基线；消费方跟随升级固定 rev 即可，不单独跟踪上游分支。
- 若出现上游继承解析失败，通常是快照未初始化或指向未展开内容，先按既有 submodule 指南重新初始化再排查。
- 若出现 gpui 签名错位，以本仓库基线为准对齐，不在消费方侧打补丁。

## 5. 非目标

通用组件、编辑器、主题、后端客户端、领域面板、校验回放、多窗口均由消费方在 gpui 之上自建，不在本方案的保证范围内。
